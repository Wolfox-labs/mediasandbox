# 工作流与画布

> 这份文档回答三件事：工作流是什么、怎么跑、画布上看到的状态从哪来。

## 1. 工作流是什么

一条工作流是一张**有向无环图**：节点是一次工具调用，边是"某个输入端口取自上游某个产出端口"。

```json
{
  "id": "poster",
  "envType": "image",
  "nodes": [
    { "id": "brief", "toolId": "poster-brief", "inputs": { "goal": { "value": "校园二手市集" } } },
    { "id": "render-story", "toolId": "poster-render",
      "inputs": { "brief": { "from": "brief", "port": "brief" }, "sizeId": { "value": "story" } } },
    { "id": "export-story", "toolId": "poster-export",
      "inputs": { "file": { "from": "render-story", "port": "file" }, "sizeId": { "value": "story" } } }
  ]
}
```

三种输入来源：

| 写法 | 含义 |
|---|---|
| `{ "value": ... }` | 字面量参数 |
| `{ "from": "node", "port": "p" }` | 取上游一个产出 |
| `{ "from": [{ "nodeId": "a", "port": "p" }, ...] }` | 多上游扇入成数组（顺序即声明顺序） |

另有 `dependsOn: ["assemble"]`：给**入参里没有上游引用、但必须先跑完**的节点用。典型是 `verify-artifact` 与 `screenshot-page`——它们读沙盒里的文件，不接端口。

## 2. 预设

| id | 适用 | 说明 |
|---|---|---|
| `poster` | image | 一次执笔，竖版 / 方形 / 横版 / A4 四尺寸各出 HTML + PNG；`background: true` 时先搜一张实景图当背景，`logo` 叠品牌落款 |
| `page` | webpage | 整页模板展开成固定 DAG：执笔 → 逐块填充 → 组装 → 校验 →（可选）截图 |

预设是**代码里生成的定义**，参数（goal、templateId）来自每次请求；用户自建的工作流存成 `data/workflows/<id>.json`。

运行：

```bash
curl -X POST http://127.0.0.1:8787/api/workflows/poster/run \
  -H 'content-type: application/json' \
  -d '{"goal":"校园二手市集"}'
```

返回 `runId`，之后与普通运行一样：`GET /api/runs/:id` 查状态与产物，`/api/runs/:id/artifacts/:name` 下载。

## 3. 缓存：改一个节点只重跑它和下游

节点级缓存键 = `版本号 + 代码盐 + 工具 id + 解析后的入参哈希`。于是：

- 入参没变 → 直接复用上次结果（产物文件也会被恢复进新沙盒）；
- 改了某节点参数 → 它的键变了 → 它重跑；
- 它的产出变了 → 下游的键跟着变 → 下游重跑；
- 旁支没动 → 继续命中。

"重跑此节点及下游"就是给这次运行传 `forceNodes: ["节点 id"]`：只让这些节点当作没缓存，其余逻辑完全一样。

代码/模板改了但入参没变时，换 `MEDIASANDBOX_CACHE_SALT` 即可让旧缓存失效（不必手删目录）。

## 4. 画布

入口：`/workflows`（侧边栏「工作流画布」）。

- 左栏：工作流列表 + 最近运行（点一条可把当时的节点状态铺回画布）；
- 中栏：图。滚轮缩放、空白处拖拽平移、拖节点改位置、点节点选中；
- 右栏：检查器。可改字面量参数、查看该节点最近一次的耗时/摘要/错误，以及「重跑此节点及下游」。

状态来源是 `GET /api/runs/:id` 的 `nodeStates`——服务端从已落盘事件折出来的，所以**刷新页面也还在**，不是只存在于某一次会话里。

## 5. 边界（刻意没做）

| 没做 | 原因 |
|---|---|
| 在画布上新建节点/连边 | 需要先有"端口类型校验 + 实时保存"的交互设计；当前先用 JSON/PUT 保存，画布负责看与调参 |
| 演示文稿预设 | 幻灯片结构由决策模型逐页选版式，静态展开会得到一个"每页都一样"的预设，价值不大 |
| 缓存目录按项目隔离 | 现在是全局一份；同一份内容在不同项目间复用其实是优点（省一次生成） |
| 节点级计费统计 | 事件里已有各节点耗时，成本要等图像端点的计费口径确定后再加 |
