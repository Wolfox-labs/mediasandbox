### W1（P0）并发上限与队列 —— B-D2

- **目标**：给"同时能跑几个运行"一个明确的上限和排队语义。
- **为什么现在做**：现在每来一个 `POST /api/runs` 就直接起一次运行，没有全局上限。
  演示时点几下没问题，批量提交会把 CPU / 内存 / 容器数一起推上去（Docker 下每个运行一个容器）。
- **范围**：`packages/server`（`createServer` 入参 + 排队与放行逻辑 + 界面可见的 `queued` 状态 + 测试）；
  `packages/web` 只加一个状态显示，不改交互。
- **验收标准**：
  1. 超过并发上限的运行进入 `queued`，并在放行后自动开始，不需要重新提交；
  2. 队列满时**明确拒绝**（HTTP 429 + 说明），而不是无限堆积；
  3. 排队中的运行能被 `/api/runs` 与详情接口看到（状态 + 队列位置）；
  4. 服务重启后队列**不恢复**（不做幽灵运行）——重启后这些运行标记为"已取消（服务重启）"；
  5. 新增用例覆盖：并发上限、排队放行、队列溢出 429、重启后不恢复。
- **需要你拍板**：默认并发数（我建议 2）、队列长度（建议 16）、溢出行为（我建议 429）。

### W2（P0）交互验证接入 HTTP 与工作台

- **目标**：把已经跑通的"真浏览器点一下"变成**能在演示里点出来**的能力。
- **为什么现在做**：目前它只存在于 orchestrator 的 `verifyInteraction()` 和两个探针脚本里，
  界面上完全看不到——演示时只能靠命令行，价值被埋住了。
- **范围**：`packages/server` 加 `POST /api/runs/:runId/verify-interaction`（可选参数：指定 block 或自动挑）；
  `packages/web` 在运行详情里加"交互验证"区块：一个按钮 + 判定结论 + 点击后截图缩略图。
- **验收标准**：
  1. 对一次已成功的运行点按钮 → 返回"通过/未通过 + 原因"，并留下 `artifacts/click.png`；
  2. 页面上没有可点元素时如实说明"未做点击验证"，不报成功；
  3. 驱动不可用（Docker 不在）时返回明确原因，不静默降级成"通过"；
  4. 新增用例：接口成功路径、无可点元素路径、驱动不可用路径。
- **需要你拍板**：验证是**按钮触发**（我建议，因为要点真浏览器、耗时 3–10 秒）还是随运行自动跑。

### W8（P1）自定义 block 的生命周期管理

- **背景（已核对代码，不是猜测）**：block 池本身是做完的——
  内置 15 类 / 3 组；`POST /api/blocks` 能注册自定义 block（形态校验、拒绝与内置重名、
  只持久化外部来源），管理端 `BlockForm.vue` 有新建表单，`renderCustomBlock` 会按 slot 声明
  出 title / text / code / link / image / list / list-image，**不落占位块**。缺的是后半程：
  1. **不能改、不能删**：没有任何 `PUT/DELETE /api/blocks/:id`，管理端表单只有"新建"。
     建错了或想下线，只能手改 `data/blocks.json` 再重启——这不是可交付的运维方式；
  2. **池子的使用情况看不见**：某个自定义 block 被哪些运行用过、被决策层选中过几次，没有聚合视图；
  3. **两条规则没有写进文档**：列表型 slot 必须带 `countRange`（否则注册表直接拒绝）、
     自定义 block 的图片在确定性路线下是**占位图**（不调生成模型就没有真图）。
- **范围**：`packages/server`（改/删两个路由 + 拒绝"内置 block 不可改" + 持久化同步 + 用例）、
  `packages/admin`（列表里加编辑/删除入口）、`packages/web` 不动。
- **验收标准**：
  1. 改一个自定义 block 的 label / slot 声明后，`GET /api/blocks` 立即反映，重启后仍在；
  2. 删除后不再出现在候选集里；**内置 block 一律拒绝修改与删除**（400 + 说明原因）；
  3. 删除一个已经被历史运行用过的自定义 block：历史记录照样能查（结构里存的是落定后的内容，
     不依赖池子还在）——这条要有用例锁住；
  4. W3 的文档订正里补上上面第 3 条背景里的两条规则。
- **删除行为（两种都写在这里，实施前再定；本计划不替人做这个选择）**：
  - **停用**：从候选集移除，历史仍可读。实现上是给外部 block 加 `disabled` 标记，
    `GET /api/blocks` 默认不带出，`?includeDisabled=1` 可查；
  - **物理删除**：从注册表与 `blocks.json` 里摘掉。仅对**从未被任何运行用过**的 block 允许，
    否则拒绝并说明"已被历史运行引用"（历史记录里存的是落定后的内容，不依赖池子仍在）。
- **需要你拍板**：W8 做 / 不做；做的话删除采用上面哪一种。

## 三、明确不做（避免以后反复讨论）

1. **不引入第三方大模型**（除 W5 经你批准之外），决策层可继续用内置演示层或 Rizzo；
2. **不把 chromium 塞进项目镜像**：浏览器始终是旁挂容器；
3. **不做队列持久化 / 幽灵运行**（见 W1 第 4 条）；
4. **不做鉴权与多租户**：当前定位是本地单机演示；
5. **不为点击驱动去掉只读根**：宁可多一层 socat，也不放宽容器约束。
