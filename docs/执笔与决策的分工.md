# 执笔与决策的分工（本项目的模型角色约定）

用户的原话：**"用大模型做主要模型，决策模型是用来做决策的"**。

这句话定的是**谁写、谁选**的边界，不是两个模型谁更重要。下面把它落到代码上。

## 一、两个模型各干什么

| 角色 | 谁 | 干什么 | 不该干什么 |
|---|---|---|---|
| **执笔（主要模型）** | 大语言模型 `LlmClient` | 写内容：整份文稿/整页的文案，一次写连贯的一段，而不是逐 slot 填空 | 不决定结构、不选版式、不选主题 |
| **决策（决策模型）** | 决策模型 `DecisionClient` | 只做**封闭选择题**：下一块/页用什么、要不要继续、要几项、主题、构图节奏 | 不写任何一段正文 |

分工的判据很简单：**开放生成 → 大模型；从有限候选里挑一个 → 决策模型**。
任何一处让大模型"决定结构"，或让决策模型"写正文"，都是跑偏。

## 二、之前的差距（已修复）

在 `a1854c8` 时，上表只有一处不符合约定：**正文是逐 slot 独立生成的**。
同一个要点页的标题、导语、五个条目是五次独立调用，模型不知道邻居写了什么，
更不知道上一页讲了什么。表现就是：

- 各页之间没有承接（这一页讲增长，下一页又从头讲一遍背景）
- 同一页内条目风格不齐（有的 8 字有的 20 字）
- 措辞重复（每页都在"通过数据洞察……"）

这不是版式的问题，是**执笔被切碎了**。

## 三、现在的实现：一次执笔

链路改成：

```
统筹规划（大模型，出结构计划）
      ↓
结构决策（决策模型，选页序/版式/主题/构图 —— 只从候选里挑）
      ↓
一次执笔（大模型，按已定稿的页序与版式，一次写出整份文稿的每页文案，JSON）
      ↓
fill-slide（确定性落位；只对执笔没写到的 slot 回落到逐 slot 生成）
      ↓
渲染（确定性代码，把文案放进选中的版式）
```

落点：

1. `structured/deck-write.ts`：一次调用写出 `{ pages: [{ slots: {...} }] }`。
   提示词带目标、统筹计划、主题、页序、每页版式、每个 slot 的名字/类型/项数；
   输出按页索引与 slot 名对齐，只收该版式声明过的可写 slot。
2. `structured/deck-tools.ts`：`fill-slide` 增加 `written` 入参（该页文案 JSON）。
   有它就优先落位；没覆盖的 slot 才回落到 `generate` / 确定性内容。
3. `structured/deck-assembler.ts`：页序定稿后、建节点前调用一次执笔，
   把每页结果作为**字面量**传进对应的 `fill-slide` 节点。失败则如实记
   "执笔不可用"，并让整份文稿回落到逐 slot 生成。
4. `structured/planner.ts`：`askSlotSource: false`。一次执笔下"谁写"不再是
   决策问题，不再逐 slot 发 `slot_source` 问句（少一轮决策往返）。
5. 测试：`deck-write.test.ts` 验"多页来自同一次调用"与解析边界；
   `filler.test.ts` 验执笔优先、缺 slot 兜底、条数/类型/长度校验；
   `server/src/deck.test.ts` 端到端断言整份文稿只有**一次**生成调用。

## 四、不要把边界搞反的三条

1. **决策模型不做"总结/润色"**：让它写一段话，等于让一个只会做选择题的模型写作文。
2. **大模型不选版式**：即使它"顺便"说"这页适合用数据页"，也只当建议，
   真正选哪个由决策模型的 `choice` 回答。
3. **两者的错误要能分开**：文案差 → 换写作模型；版式/页序不合理 → 决策模型或候选池的问题。
   现在这两类问题混在一起，调优时最容易被误导。
