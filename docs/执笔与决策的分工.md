# 执笔与决策的分工（本项目的模型角色约定）

用户的原话：**"用大模型做主要模型，决策模型是用来做决策的"**。

这句话定的是**谁写、谁选**的边界，不是两个模型谁更重要。下面把它落到代码上。

## 一、两个模型各干什么

| 角色 | 谁 | 干什么 | 不该干什么 |
|---|---|---|---|
| **执笔（主要模型）** | 大语言模型 `LlmClient` | 写内容：整份文稿/整页的文案，一次写连贯的一段，而不是逐 slot 填空 | 不决定结构、不选版式、不选主题 |
| **决策（决策模型）** | 决策模型 `DecisionClient` | 只做**封闭选择题**：下一块/页用什么、要不要继续、要几项、主题、构图节奏 | 不写任何一段正文 |

分工的判据很简单：**开放生成 → 大模型；从有限候选里挑一个 → 决策模型**。
任何一处让大模型"决定结构"，或让决策模型"写正文"，都是跑偏。

## 二、现状与差距（截至 `a1854c8`）

| 环节 | 现在谁做 | 是否符合上面的约定 |
|---|---|---|
| 内容计划（几段、讲什么） | 大模型（`plan/blueprint.ts`） | ✅ |
| 页序与版式 | 决策模型（`structured/planner.ts`） | ✅ |
| 视觉主题 + 构图节奏 | 决策模型（`deck-theme.ts`，同批问） | ✅ |
| 正文文案 | **大模型，但逐 slot 独立生成** | ⚠️ **部分符合** |

差距只有一处，但很关键：**逐 slot 生成 = 碎片化执笔**。
同一个"要点页"的标题、导语、五个条目是五次独立调用，模型不知道邻居写了什么、
更不知道后一页写了什么。表现就是：

- 各页之间没有承接（这一页讲增长，下一页又从头讲一遍背景）
- 同一页内条目风格不齐（有的 8 字有的 20 字）
- 措辞重复（每页都在"通过数据洞察……"）

这正是"看起来像模板填出来的"的根因——**不是版式的问题，是执笔被切碎了**。

## 三、该怎么改（下一步的工作）

把"逐 slot 填充"换成**一次执笔**：

```
统筹规划（大模型，出结构计划）
      ↓
一次执笔（大模型，按计划一次写出整份文稿的每页文案，JSON）
      ↓
结构决策（决策模型，选页序/版式/主题/构图 —— 只从候选里挑）
      ↓
渲染（确定性代码，把文案放进选中的版式）
```

落点：

1. `structured/deck-write.ts`（新）：一次调用写出 `{ pages: [{ layout?, title, blocks: {...} }] }`，
   带完整上下文（目标、计划、主题、页数上限），输出按版式 slot 名对齐
2. `structured/deck-tools.ts`：`fill-slide` 优先用"执笔结果"里的文案（按页索引取），
   取不到才回落到逐 slot 生成 —— **降级路径要留着**，因为大模型可能没配或失败
3. `server/src/app.ts`：演示文稿的默认从"逐 slot 生成"改为"一次执笔"，
   `useGenerative:false` 仍然走确定性填充
4. 测试：断言同一份文稿里，各页文案来自**同一次调用**（用 mock 计数），
   并且页数、slot 名与结构对得上

## 四、不要把边界搞反的三条

1. **决策模型不做"总结/润色"**：让它写一段话，等于让一个只会做选择题的模型写作文。
2. **大模型不选版式**：即使它"顺便"说"这页适合用数据页"，也只当建议，
   真正选哪个由决策模型的 `choice` 回答。
3. **两者的错误要能分开**：文案差 → 换写作模型；版式/页序不合理 → 决策模型或候选池的问题。
   现在这两类问题混在一起，调优时最容易被误导。
